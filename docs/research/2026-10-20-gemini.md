# Gemini in Nuzky (20 Oct 2026)

Research by GPT-6.1 Sol (Codex) with the conclusions checked by Claude Opus 5.5, for the question whether the AI panel can run Gemini on the user's own Google account as it runs Claude Code and Codex. Nobody had a Gemini subscription or a Google API key, so every run used the real binaries against a fake Gemini API on 127.0.0.1, with an isolated home folder and no real account, keyring or Google API. Each point says whether it was **run** or **read**. Harnesses and captures: `tmp-test/gemini-research/`, `tmp-test/agy-research/` (not committed).

## Verdict

- **Gemini CLI: not for personal accounts.** **Read:** Google stopped serving Gemini CLI for free accounts, Code Assist for individuals, Google AI Pro and Ultra on 18 June 2026 ([announcement](https://github.com/google-gemini/gemini-cli/discussions/27274), [deprecation](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)). It stays for paid Gemini API keys and enterprise licences. **Run** on 0.64.0: it could be held to Nuzky's tools (its own `GEMINI_CLI_HOME`, `tools.core: []`, `--allowed-mcp-server-names nuzky`, a `--policy` allowing `mcp_nuzky_*`), resumes after SIGINT and takes a JPEG, but that serves almost nobody who would use the panel.
- **Antigravity CLI (`agy`), its replacement: not in the panel.** **Read:** the [Antigravity Additional Terms](https://antigravity.google/terms), clause 6, call "using third party software, tools, or services to access the Service" a breach and name suspension of the Google account as a consequence. Nuzky starting `agy` on the user's account would be that. **Run** on 1.4.3 it could not be isolated either: even a restricted custom agent keeps the built-in `manage_task`; the user's global MCP servers, hooks, skills and `GEMINI.md` load, and no flag turns them off; attached pictures cannot be passed (stream input takes text only); `init.tools` does not show what the model is offered.
- **Gemini in a terminal, connected to Nuzky: shipped.** The user runs `agy` themselves; Connect puts Nuzky's MCP server into its settings. That is Google's own client using a documented feature, and the agent edits the open project like Claude Code or Codex in a terminal.
- **A Gemini API key in the panel: possible, not built.** **Read:** the [Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview) with `store: false` would let Nuzky run Gemini as it runs ChatGPT, and the [pricing page](https://ai.google.dev/gemini-api/docs/pricing) (19 Oct 2026) lists a free tier for Flash models, whose content Google may use and human reviewers may read. The [Gemini API terms](https://ai.google.dev/gemini-api/terms) ask for paid services when an API client is offered to users in the EEA, Switzerland and the UK, limit use to professional purposes and to people over 18; how that applies when every user brings their own key is not stated. Google offers no "Sign in with Google" for other apps to use a Gemini plan.

## Facts Connect relies on (agy 1.4.3, Linux)

- **Run:** user-wide MCP servers live in `~/.gemini/config/mcp_config.json`, strict JSON (`agy mcp list` rejects comments; a turn with a broken file runs without its servers). `{"command", "args"}` is enough; `type` and unknown keys are accepted. `agy mcp disable` writes `"disabled": true`. The desktop app's older `~/.gemini/antigravity/mcp_config.json` is not read by the CLI.
- **Run:** agy starts a stdio server with its whole environment, the entry's `env` on top, in its launch folder, so the server finds Nuzky's socket under `XDG_RUNTIME_DIR` without help.
- **Run:** interactive agy asks before every Nuzky tool, with six choices; "always allow" covers one tool, in the conversation or in settings. `"permissions": {"allow": ["mcp(nuzky/*)"]}` in `~/.gemini/antigravity-cli/settings.json` removes the question ([permissions](https://antigravity.google/docs/permissions/)); agy refuses to start with an invalid settings file.
- **Run:** `agy mcp` has add, remove, list, enable and disable; none starts a server, so Connect's check starts the entry's command itself. `agy --version` prints `1.4.3` in about 0.4 s and touches no network, keyring or file.
- **Run:** no command says offline whether agy is signed in. The first run without credentials asks "Select login method: 1. Google OAuth 2. Use a Google Cloud project".
- **Run:** Esc or the first Ctrl+C cancels agy's turn but keeps the MCP connection open, so Nuzky's Stop still matters; quitting agy closes it.
- **Run:** the installer puts `agy` in `~/.local/bin` and adds it to `PATH` only in shell profiles that already exist, so a new terminal may not find it; the guide gives the full path.
- **Not verified:** a real Google sign-in and plan, macOS, quotas (free accounts get a weekly quota with no published numbers), and whether a Google account behaves as the API-key mode used for every run.
